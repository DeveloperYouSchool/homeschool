# Talk it out  
Let's discuss how we would define a problem before we try solving it. Knowing what the problem is can help you break it down into its components.  
## Hans has a list  
Hans was working with a list of people who have been working through some test lessons. Eventually, he had about 100 names. We initially talked about a certificate template and plugging the names in as they finished.  

Then we took a weekend off.  

By Monday we had about 30 more names. It took over an hour to type all of those names in and send the certificates off!  

## Talk through the problem  
### A lot of names  
When we look at the list, what we usually see is all the work we have left to do. We can break this down by just looking at the first entry and asking ourselves what we have to do with it.  

### Did we already make their certificate  
In a real situation, we'd want to make sure we don't accidentally issue the same certificate to a person multiple times. We could either add an 'issued' flag to this record, or remove it from the file once we've issued the certificate.  

### An empty certificate  
Whether we add our information to a certificate template or create new files each time, we want to add the current record to some existing content and send it off.  

## Put it together  
Now that we've looked through this situation, Hans has a good idea of how we'll handle the task.  

- Read the name, class, completion date, and email address  
- Create the certificate  
- Send the certificate to the participant  
- Move to the next name
